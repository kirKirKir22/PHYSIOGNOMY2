Документ описывает **каждый класс/объект/файл** приложения: где лежит, что внутри и за что отвечает.
Пути указаны относительно корня проекта `C:\Users\Kirll\AndroidStudioProjects\physiognomy2`.

Стек: Kotlin + Jetpack Compose + Material 3, архитектура «один экран — Compose + общий `AndroidViewModel`».
Нет Room, нет DI, нет сети: всё состояние хранится в `SharedPreferences` и файлах во внутренней папке приложения.

## 1. Точка входа

### `MainActivity` — `app/src/main/java/com/kirill/physiognomy2/MainActivity.kt:14`
Единственная Activity (`ComponentActivity`).

- `onCreate`: `enableEdgeToEdge()`, затем `setContent { ... }`.
- Создаёт `ThemeController` через `rememberThemeController()`.
- `DisposableEffect(dark)` переключает цвет иконок статус-бара/навбара через `WindowCompat.getInsetsController`.

## 2. Слой данных (`data/`)

### `PhysiognomyCatalog.kt`

Файл содержит и модель, и сам контент-каталог (204 варианта ответа захардкожены прямо в коде).

#### `enum class EyeShape` — `PhysiognomyCatalog.kt:5`
Пять форм разреза глаз: `Almond, Round, Narrow, Drooping, Raised`.
Нужен только для того, чтобы UI на шаге 3 мог нарисовать иконку глаза (`FeatureArt`/`EyeShapeArt`).

#### `enum class Section` — `PhysiognomyCatalog.kt:7`
Три смысловых раздела чек-листа с диапазонами шагов:
- `FaceTraits` (1–16) — «Чтение черт лица»,
- `ExtraElements` (17–19) — «Дополнительные элементы лица»,
- `FaceTypes` (20–26) — «Общие формы и типы лица».
Используется в `ChecklistScreen` и `ReferenceScreen` для группировки шагов.

#### `data class AnswerOption` — `PhysiognomyCatalog.kt:14`
Один вариант ответа: `id`, `label`, `traits: List<String>`, `description`, необязательный `eyeShape`.
`@Immutable` — подсказка Compose-компилятору для оптимизации рекомпозиции.

#### `data class Question` — `PhysiognomyCatalog.kt:23`
Вопрос шага: `id` (формат `s7q2`), `title`, `options`.

#### `data class Step` — `PhysiognomyCatalog.kt:30`
Шаг чек-листа: `number`, `title`, `subtitle`, `questions`. Свойство `id` = `"step$number"` (ключ для LazyColumn).

#### `OptionSpec` / `QuestionSpec` — `PhysiognomyCatalog.kt:39, 46`
Внутренние (`private`) «сырые» структуры для лаконичной записи каталога, где `traits` — одна строка через `;`.
В `AnswerOption` не попадают.

#### DSL-хелперы `o()`, `q()`, `step()` — `PhysiognomyCatalog.kt:48-80`
- `o(...)` — собрать `OptionSpec`;
- `q(...)` — собрать вопрос из вариантов;
- `step(...)` — собрать `Step`: генерирует id вопросов `s{N}q{i}` и id вариантов `{questionId}-{index}`, режет `traits` по `;`.
Благодаря им каталог записан компактно.

#### `object PhysiognomyCatalog` — `PhysiognomyCatalog.kt:82`
Главный реестр данных.
- `steps: List<Step>` — все 26 шагов (строки 84–543).
- `totalQuestions` — 44 (считается из `steps`).
- `totalOptions` — 204 (считается из `steps`).
- `questionsById`, `stepByNumber` — приватные индексы для O(1) поиска.
- `step(number)` — шаг по номеру, с fallback на первый.
- `question(id)`, `option(optionId)`, `optionLabel(questionId, optionId)`, `optionLabelById(optionId)` — поиск по id (id варианта парсится через `substringBeforeLast('-')`).
- `stepOf(questionId)` — номер шага из id вопроса (`s7q2` → 7).

> Важно: id вопросов/вариантов — это «контракт» между каталогом, `answers` в prefs, `TraitReading.questionTerms` и тестами. Менять их без миграции нельзя.

### `ResultComposer.kt`

Чистая логика «превратить ответы в текст», без Android-зависимостей (поэтому тестируется JUnit’ом).

#### `object ResultComposer` — `ResultComposer.kt:5`
- `data class Answered(step, question, option)` — один выбранный ответ, развёрнутый по каталогу.
- `data class ReadingBlock(area, entries, terms)` — смысловая группа результата (`area` + какие ответы в неё попали + термины).

Методы:
- `answered(answers)` — проходит по всему каталогу и собирает только валидные выборки; неизвестные/битые id молча игнорируются (`:13`).
- `missing(answers)` — список пар «шаг + неотвеченный вопрос» (`:22`).
- `readingBlocks(answers)` — группирует ответы по `ReadingArea`, собирает термины, сортирует блоки по количеству ответов (`:39`). Пустые группы не попадают.
- `profileTitle(answers)` — заголовок итога: самое частое качество из `traits` (фильтр по длине 4..40 символов) → «Ведущая черта — …» (`:51`).
- `buildText(answers, name)` — полный текстовый портрет для копирования/шаринга: шапка, счётчик, ключевые качества, блоки «что читается», разбор по шагам, общий вывод, список пропусков (`:70`).
- `buildConclusion(answered)` — эвристика: считает вхождения корней слов в 6 «шкалах» (ум/чувства/воля/общительность/осторожность/творчество) и пишет 2–3 предложения + оговорку про «не приговор» (`:146`).
- `traitWord(count)` — русское склонение «черта/черты/черт».
- `score(text, roots)` — число вхождений корней через `Regex`.

### `TraitReading.kt`

Справочник «что читается по черте» — отдельно от каталога, чтобы текстовые подписи не дублировались.

#### `enum class ReadingArea` — `TraitReading.kt:6`
9 смысловых областей с привязкой к номерам шагов: `Thinking` (1–2), `Perception` (3–6), `Work` (7), `Interaction` (8), `SelfEsteem` (9, 17), `Speech` (10–13), `Will` (14–16), `Experience` (18–19), `Whole` (20–26).
Используется в шапке шага, в блоках итога и в справке.

#### `object TraitReading` — `TraitReading.kt:18`
- `stepTerms: Map<Int, List<String>>` — базовые термины для каждого шага (`:20`).
- `questionTerms: Map<String, List<String>>` — уточнения для отдельных вопросов (`s7q5` и т.п.), перекрывают `stepTerms` (`:73`).
- `unverifiedQuestions` — вопросы-«дополнения приложения» (сейчас `s3q1`), в UI помечаются подписью «Дополнение приложения» (`:160`).
- `areaFor`, `areaTitleFor` — область по номеру шага.
- `termsFor(stepNumber, questionId)` — сначала ищет override по вопросу, иначе базовые термины шага.
- `readingFor` — термины одной строкой; `shortReadingFor` — обрезает до `limit` с «…».
- `isUnverified(questionId)` — флаг для бейджа.

## 3. Состояние приложения

### `WorkspaceViewModel` — `app/src/main/java/com/kirill/physiognomy2/ui/workspace/WorkspaceViewModel.kt:45`
`AndroidViewModel`, единственный источник истины для ответов, навигации по шагам, фото и профилей. Живёт на уровне Activity, поэтому переживает переключение вкладок.

Хранит состояние в Compose-типах (`mutableStateOf`, `mutableStateMapOf`, `mutableStateListOf`), поэтому UI перерисовывается автоматически.

**Навигация по чек-листу**
- `stepNumber`, `questionIndex` (private set) — где пользователь сейчас.
- `step`, `question` — текущие шаг/вопрос с защитой индексов.
- `openStep(number)` — открыть шаг и встать на первый неотвеченный вопрос.
- `focusQuestion(index)`, `nextQuestion()`, `skipQuestion()`, `previousQuestion()`.
- `isLastQuestionOfStep`, `isLastStep`, `canGoBack` — флаги для кнопок.
- `goToLastStep()` — не используется в UI, но оставлен как утилита.

**Ответы**
- `answers: SnapshotStateMap<String, String>` — `questionId → optionId`.
- `selectOption`, `clearOption` — запись/удаление с сохранением в prefs.
- `answeredTotal`, `answeredInStep(number)`, `answerFor(questionId)`.

**Фото**
- `photos: SnapshotStateList<PhotoItem>`, `currentPhotoIndex`, `currentPhoto`, `effectsEnabled`.
- `addPhotos(uris)` — асинхронный импорт: ограничение `MAX_PHOTOS = 10`, декодирование с downscale (`decodeSampledBitmap`, `MAX_PHOTO_SIDE = 1800`), учёт EXIF-поворота (`applyExifRotation`), сохранение JPEG в `filesDir/photos`, обработка ошибок и сообщений (`photoNotice`).
- `selectPhoto`, `deleteCurrentPhoto`, `deletePhotoAt` (последний в UI не вызывается).
- `setBrightness`, `setContrast`, `toggleGrayscale`, `toggleMirror`, `resetPhotoEffects`, `commitPhotoEdits` — правки текущего фото (яркость/контраст пишутся «на отпускание» ползунка).
- `toggleEffects` / `ensureEffectsEnabled` — режим «показать оригинал»; любая правка автоматически включает эффекты обратно.
- `deleteAllPhotos()` — чистит и список, и файлы.

**Профили**
- `profiles: SnapshotStateList<Profile>`, `activeProfileId`, `activeProfileName`.
- `saveCurrentProfile(name)` — обновляет активный профиль или создаёт новый (`:381`). ⚠️ В ветке создания не выставляет `activeProfileId`/`activeProfileName` (баг из отчёта проверки).
- `defaultProfileName()` — «Профиль N» по максимальному номеру.
- `loadProfile`, `renameActiveProfile`, `startNewProfile`, `deleteProfile`.

**Сброс и персистентность**
- `resetAnswers()` — чистит ответы и возвращает на шаг 1.
- `load()` (`:468`) — восстанавливает шаг, вопрос, ответы, фото (только существующие файлы), профили и активный профиль из `SharedPreferences`.
- `persistNavigation`, `persistAnswers`, `persistPhotos`, `persistProfiles` — запись JSON-строк/prefs.
- Константы: `PREFS_NAME`, ключи, `MAX_PHOTOS`, `MAX_PHOTO_SIDE`, `PHOTO_QUALITY`, `PROFILE_NAME_PATTERN`.

**Модели в этом же файле**
- `data class PhotoItem(path, brightness, contrast, grayscale, mirrored)` — фото и его неразрушающие правки (`:30`).
- `data class Profile(id, name, createdAt, answers)` — сохранённый разбор (`:38`).

## 10. Как всё связано (поток данных)

```
Пользователь
   │ tap
   ▼
StepPanel / PhotoStage / ProfilesScreen / ResultScreen / SettingsScreen   (Compose UI)
   │ колбэки
   ▼
AppRoot  (NavHost, передаёт один WorkspaceViewModel)
   │
   ▼
WorkspaceViewModel  ──►  SharedPreferences + filesDir/photos
   │ Compose State         (ответы, шаг, фото, профили, тема)
   ▼
StepPanel / ResultScreen
   │ читают
   ▼
PhysiognomyCatalog (какие есть шаги/вопросы/варианты)
TraitReading       (что читается по черте)
ResultComposer     (ответы → текст портрета)
```

- **Каталог** — единственный источник «что можно выбрать».
- **Ответы** — карта `questionId → optionId`; всё остальное (названия, качества, описания) восстанавливается из каталога.
- **`TraitReading`** — только справочные подписи, не влияет на сохранение.
- **`ResultComposer`** — вся «аналитика»: заголовок, блоки, итоговый текст.
- **UI** не хранит своё состояние, кроме эфемерного (диалоги, скролл, зум).
